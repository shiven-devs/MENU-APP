## What I learnt

### Next.js App Router

- Default is a **Server Component**: it can talk to Mongo and read secrets. It cannot use `useState` or `onClick`.
- `"use client"` only when the browser is required (forms with `useActionState`, sticky category tabs, `error.tsx` “Try again”).
- **Server Actions** (`"use server"`) for in-app form saves. **Route Handlers** (`app/api/...`) only when something outside the app must call HTTP — Auth.js and a public JSON menu API.
- `error.tsx` must be a Client Component even if the page that crashed was a Server Component: the crash is on the server; the retry **button** runs on the phone.
- Next.js 16 uses **`proxy.ts`**, not `middleware.ts`, for request-time redirects.

### Auth.js (split config)

- `proxy.ts` runs at the “front door” (Edge). It may only glance at the session cookie. It must **not** import Mongo or bcrypt.
- Password check lives in `lib/auth.ts` → `authorize()` (Node): find user, `bcrypt.compare`, issue a JWT cookie.
- That is why there are two files: `auth.config.ts` (Edge-safe) and `auth.ts` (adds Credentials + database).

### Server vs client in *this* UI

- **`ItemCard`** — Server Component: it only displays a dish.
- **`CategoryTabs`** — Client Component: click-to-scroll and highlight-on-scroll need `document` and `useState`.
- A Server page can render a Client child. Pass **plain objects** (`{ id, name }`), not Mongoose documents.

### Data (MongoDB)

- Menu data is linked: restaurant → categories → items. Mongo stores them as separate documents with `restaurantId` / `categoryId`.
- Mongo does **not** auto-delete child dishes when you delete a category. We do it in code: `MenuItem.deleteMany` then `Category.deleteOne`.
- Supabase/Postgres would enforce that in the database. For this repo we **keep Mongo** — switching now is a rewrite, not an upgrade. Cart later can be a new `orders` collection.

### Images and QR

- Dish/logo/cover photos upload via a Server Action to **Cloudinary** (secrets stay on the server). `next/image` is for those hosted URLs.
- QR is drawn **on the server** with `qrcode` so `APP_URL` stays server-only. Phones need a full URL (`https://…/r/slug`), not `/r/slug`. Preview uses a normal `<img>` because a `data:` PNG is not a Cloudinary file.

### Product thinking

- Unique-per-table QRs only matter when an order must know **which table**. View-only menu = one QR. Don’t build cart UI now; don’t block `?table=` for later.
